# Decision log

Every decision in this project: what was chosen, why, and what else was considered.

## Made

| # | Date | Decision | Why | Alternatives considered |
|---|---|---|---|---|
| 1 | 2026-11-20 | Keep the design doc and this log as Markdown inside the repo (`docs/`). | Reviewers get the design and the code in one place, and git tracks changes to both. | A separate Google Doc or PDF. |
| 2 | 2026-11-20 | Use **uv** to manage Python and dependencies. | One tool installs the right Python version, creates `.venv`, and writes a lockfile (`uv.lock`) so the reviewer gets the exact same versions. | `python -m venv` + `pip` + `requirements.txt` (more steps, no automatic lockfile). |
| 3 | 2026-11-20 | Pin **Python 3.13**. | On Python 3.15, `comtypes` (used by `uiautomation`) prints a compatibility warning. 3.13 is stable and fully supported. | Stay on 3.15.2 and live with the warning. |
| 4 | 2026-11-20 | Keep the structure simple: a few small modules, no framework. | The task is one linear flow. Simple code is easier to explain line by line. | Plugin architecture, classes for every screen, a test framework from day one. |
| 5 | 2026-11-21 | Extract with a **vision LLM, Google Gemini on the free tier**, returning schema-checked JSON, cached as `samples/order.extracted.json` (`--from-json` skips the model). | It reads the structure, not just text. Validation catches its mistakes. It costs nothing: one call per image, and the cache makes re-runs free and lets reviewers run without a key. | A paid model such as Claude (no free API tier); a local model via Ollama (free and offline, but a multi-GB download); Windows OCR plus parsing rules (free and offline, but tied to this one layout). |
| 6 | 2026-11-20 | Use the **`uiautomation`** library. | It was used to inspect Fakturama, and it worked with SWT controls and patterns. Its API is small. | `pywinauto` (UIA backend): bigger, with more ways to do the same thing. |
| 7 | 2026-11-20 | Read custom-drawn tables with the **app's own copy** (focus, Ctrl+A, Ctrl+C), guarded by an **OCR "has rows?" check**. | Copy returns exact raw values. Copying an empty table crashes Fakturama (UI-MAP G7). | OCR for all table text (misreads); reading the database directly (bypasses the UI). |
| 8 | 2026-11-20 | Find unnamed inputs by **label anchoring**, and unnamed icons by **order next to their label**, clicked at their runtime UIA rectangle. | No hardcoded coordinates, and it survives window moves and resizes. | Coordinates (forbidden by the brief); screen vision for every click (slow, costly). |
| 9 | 2026-11-20 | **Stop for manual review** on ambiguity, a failed check or an unexpected dialog. Report it with a log, a screenshot and an exit code. | Wrong accounting data is worse than a stopped run. | Best-guess matching; retrying blindly. |
| 10 | 2026-11-20 | Evidence: a **log and a screenshot per step** in `runs/<timestamp>/`, with the best ones annotated for the README. | Automatic, and shows exactly where a run stopped. | A screen recording (harder to annotate and review). |
| 11 | 2026-11-20 | Pre-flight: **stop if an Order with the same Cust.Ref. already exists**. | Re-running must not create a duplicate Order. | Allowing duplicates; updating the existing Order. |
| 12 | 2026-11-21 | Add an **OCR witness**: every text value from the LLM must roughly appear (similarity ≥ 0.7) in Windows OCR of the same image. | Math checks the numbers but can't check names or streets. A second, independent reader can. On the sample, true values score 0.80–1.00 and an invented street 0.56. It catches invented text, not one-letter typos. | Trusting the LLM for text; exact matching (OCR misreads would cause false alarms). |
| 13 | 2026-11-21 | **Type values with real keystrokes**, then read them back. `ValuePattern` is used only for search boxes. | Fakturama sometimes shows a value set through UIA but doesn't save it (UI-MAP G17). Keystrokes are what a user does. | `ValuePattern.SetValue` everywhere (faster, but loses data silently). |
| 14 | 2026-11-21 | Rows and cells of custom-drawn tables are clicked where **OCR sees their text on a fresh screenshot**. | UIA can't see rows, and selecting a row needs a real click (G20, G22). The position is computed at runtime, never written in code. | Fixed offsets from the table's corner (breaks with fonts, rows or columns); keyboard navigation (unreliable in these tables). |
| 15 | 2026-11-21 | **Resolve the payment method before opening the Debtor editor** (the brief does it from inside the editor). | An open Debtor editor doesn't refresh its payment list (G23), and the Debtor must be saved only once. The result is the same records. | Saving the Debtor twice; closing an unsaved editor (unreliable, G25). |
| 16 | 2026-11-21 | **Never close an editor with unsaved changes.** Every editor the program opens is saved once, then closed. | The "Save Parts" prompt can't be driven reliably (G25), and a wrong answer would save unwanted records. | Discarding via the prompt. |
| 17 | 2026-11-21 | Keep a **flat module layout**: one file per job (`schema`, `extract`, `validate`, `ocr`, `ui`, `flow`), with `flow.run()` listing the steps at the top of `flow.py`. The data classes live in `schema.py`, not `models.py`: in an LLM project, "model" should mean only the AI model. | The whole program is about 1,500 lines and one linear flow; a few files are quicker to navigate and explain. | Packages per stage with one module per step (tried, then reverted). The next step would be page objects (one class per Fakturama screen). |
| 18 | 2026-11-21 | **Fallback when Gemini is unavailable: other free Gemini models, then manual review.** Four models are tried in order, the fast "lite" ones first. 404, 429, 5xx and no answer within 20 s mean "try the next one". If none answers, the run stops within about a minute; `--from-json` still works. | Google's 503 "high demand" made the program look stuck, sometimes for minutes. Each model has its own capacity. Measured on 2026-11-21: 3.5-flash-lite and 3.1-flash-lite answered in about 3 s, 3.5-flash and 3.6-flash in about 17 s, all four exactly like the human reading; 3.7 and 3.8 answered 503 or hung every time. A weaker model's mistakes are caught by the same checks (math, OCR witness). Failing fast matters more than waiting: a saved reading is the real fallback. | OCR plus layout rules as the fallback reader (measured on the sample: it misreads the SKU `CHR-ERG-01` as `CHR-ERG-OI` and misses the `10%` discount); waiting and retrying (minutes of waiting, often for nothing); a paid model (not free); a local model via Ollama (multi-GB download). |
